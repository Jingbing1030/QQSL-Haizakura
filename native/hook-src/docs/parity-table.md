# 新旧对照表：闭源载荷 vs. Haizakura

**怎么读这张表。** 每一行是一个可观察的行为。"旧版"一列只写**有地址证据**的结论，
"新版"一列写**实测过的**结论。两者都不许写"应该可以"。

三档结论，分别代表完全不同的事情，不能混用：

| 标记 | 含义 |
| --- | --- |
| ✅ 等价 | 两个实现的行为都实测过，结果相同 |
| ⚠️ 未实现 | 新版没有这个行为；旧版有证据 |
| ❓ 未证明 | 两个实现都做过，但旧版的成功路径没有被追到底，所以无法断言等价 |

最后一行"未实现"比"未证明"更严重，但两者都**不能**被写成"一致"。

## 一、帧与传输层

| 行为 | 旧版（证据） | 新版（实测） | 结论 |
| --- | --- | --- | --- |
| 帧头 40 字节小端，magic `0x31504851` | `sub_1f180` 唯一写入点 | 一致 | ✅ |
| 版本号 1，非 1 拒收 | `cmp WORD [rsp+0x144],0x1` | 一致 | ✅ |
| cmd ≤ 0x1000 / msg ≤ 0x10000 / body ≤ 0x1000000 | `0x1a5a1`/`0x1a5b1`/`0x1a5be` | 4096/65536/16MiB | ✅ |
| 三段紧凑排列 cmd→msg→body | `0x1a590` 打包器 | 一致 | ✅ |
| 入站 op 白名单 | **只有 2 和 17**（`0x1183c`/`0x11846`），其余静默丢帧 | 接受 1/2/17，其余静默忽略 | ✅ 对 2/17 等价；对未知 op 都静默 |
| 出站 op | 1,3,4,5,6,7,21,22 | 1,3,4,5,6,7,21,22 | ✅ |
| 未知 op 不报错、直接丢 | `0x1184a jne 113a0` | 同 | ✅ |
| socket 权限 `srw-------` | 实测 | `fchmod 0600` | ✅ |
| 不抢占已存在的活 socket | （旧版未测） | 检测后拒绝 | ✅ 新版更严格 |

## 二、op 逐个

| op | 旧版语义（证据） | 新版 | 结论 |
| --- | --- | --- | --- |
| 1 hello | 握手；回自己的 hello，msg=pipe 名，value0=pid | 同 | ✅ |
| 2 请求（白名单外） | ACK + `Linux runtime targets are not resolved yet` | ACK + 同一句 | ✅ |
| 2 请求（白名单内 4 条） | `sub_27820` 放行 → `50c30` 解析目标 → `call [r15+0x30]` | **未实现**，仍走拒绝分支 | ⚠️ |
| 3 ACK | 回填 requestId/flags | 同 | ✅ |
| 4 reply | body 可为空 | 同 | ✅ |
| 5 error | status 为负 errno（如 -22） | 同 | ✅ |
| 6 packet | `sub_1a590` 打包；`0x1a724` op=6，`r8`=value0 会话 id，`r9`=描述符 | 已实现并通过 hook 触发 | ✅ |
| 7 登录态 | `0x14560`：status=(uin!=0)，value0=uin 数值，msg=十进制 uin；登录时广播 | 实测 `flags=4`，uin=3083456343，8s 内推送 | ✅ |
| 17 登录身份提示 | **入站**。要求 value0 ∈ [0x1_0000_0000, 0x1_0000_270F]（高 32 位=1、低 32 位<10000）；合法→回 op 3 并开 60s 窗口；非法→op 5/-EINVAL | 实测：`(1,42)`→op 3；裸 uin→op 5/-22；counter=10000→op 5/-22；60s 后 `keepalive=expired` | ✅ |
| 21 回执 | `0x1a331 mov esi,0x15`，在 op 6 之前，value0=会话 id，无载荷 | 已实现（op 6 前发送） | ✅ |
| 22 账号上报 | `0x13c08`/`0x17316` `mov esi,0x16`，value0=会话 id，requestId=(id==0)?1:0，无载荷 | 实测登录时收到 `OP22 reqId=0 value0=3083456343 cmdlen=0` | ✅ |

## 三、登录态来源

| 项 | 旧版 | 新版 | 结论 |
| --- | --- | --- | --- |
| 数据源 | QQ 注入的虚表回调 `call rax` @ `0x14917`（`rax = [obj+0xa0]`） | `auth/login.enc` 的 mtime 变化 | ⚠️ **不同机制** |
| 是否读文件系统判定登录 | **否**，所有 `open`/`stat`/`opendir` 只服务 ELF build-id 校验 | **是** | ⚠️ |
| 判定延迟 | 回调即时 | 2s 轮询 + mtime 变化 | ⚠️ 新版慢 |
| 误报风险 | 依赖回调语义 | 已排除三种假阳性（见 `login-state-from-disk.md`） | — |

这一行是**最需要说清楚**的一处：新版能拿到正确 uin，但**拿到的机制与旧版不同**。
"行为等价"只在"用户看到的结果"这一层成立，在"依赖 QQ 内部回调"这一层**不等价**。
如果 QQ 改了回调约定，旧版会失效，而新版不受影响；反过来，如果登录不写
`login.enc`，新版会漏而旧版不会。

## 四、hook 机制

| 项 | 旧版 | 新版 | 结论 |
| --- | --- | --- | --- |
| 是否 patch 代码段 | **从不**。18 处 `lock cmpxchg` 无一写代码段；`E9`/`25FF` 模式 0 命中 | **会**（函数入口 hook，仅 aarch64） | 新版多出的能力 |
| 虚表槽替换 | 是，5 个连续 `lock cmpxchg`（`0x16e95..0x16f3c`） | 是 | ✅ |
| mprotect 用途 | 5 处调用全在数据页 | 代码页（仅入口 hook 时） | — |
| 实际触发验证 | （旧版无公开证据） | **实测**：200 个 hook 装上，登录点击后最大单点命中 4122 次 | ✅ 新版已证明 |
| 安装数 | 未测 | 200/257（57 拒绝、278 太短） | — |
| 卸载安全性 | 未测 | 实测 200 个全部卸载后 QQ 存活 | ✅ |

**注意**：函数入口 hook 是**新版多出来的**，不是 parity 要求。旧版从不 patch 代码段，
所以"新版支持入口 hook"不构成任何差距；但它是新版独有的风险面（RWX 页、
I-cache 维护、prologue 重定位），必须单独承担。

## 五、还差什么（按"替换后用户会感觉到"排序）

| # | 差距 | 影响 | 严重度 |
| --- | --- | --- | --- |
| 1 | op 2 白名单内 4 条命令未实现 | 发消息、抓包、发包全部不可用。这是**产品的主功能** | P0 |
| 2 | 登录态来源与旧版机制不同 | 现在能用；QQ 改登录落盘方式就会漏 | P1 |
| 3 | 登录态判定延迟 2s 轮询 | 首帧 op 7 比旧版晚 | P2 |
| 4 | 入口 hook 的 RWX 页 | 安全面弱化，非功能缺陷 | P2 |

**只有第 1 项会让用户觉得"换了个不能用东西"。** 其余三项要么已经能用，要么只是
实现细节不同。

## 一句话

除 op 2 的发送路径外，**帧、op 1/3/4/5/6/7/17/21/22、socket 行为、虚表 hook
都已实测等价**；op 2 的发送路径是唯一的功能缺口，也是下一件必须做的事。
