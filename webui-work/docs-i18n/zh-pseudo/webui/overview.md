# Haizakura WebUI


Haizakura 之瀏覧器控制台者、管理運行時状態、OneBot 設定、記録、儲存及伺服器設定之 Vite + React 応用也。

## 既定外観

新規安裝及外観重置者、使用吉祥物之淡紫強調色也。明色版為按鈕標籤可読、使用較深之紫、暗色模式使用較柔和之淡紫。既存之保存強調色与自定色彩者保持也。元之天藍強調色者、設定中仍可利用也。

既定調色板中、頁面、卡片、輸入欄、浮層及側欄之各表面者、将少量有効強調色混入中性之明/暗背景。文本為可読性保持中性。僅限側欄之強調色者、僅側欄着色、OLED 者保持真黒之画布。具名調色板、自定 CSS 変数及宿主外観覆蓋層者、保持各自表面之控制權也。

変更既定強調色之時、伺服器側既定値者 `packages/core/src/webui/ui-config.ts` 中、前端既定値与預設者 `src/contexts/ThemeContext.tsx` 中、掛載前標記者 `src/index.css` 中、各自保持整合必要也。

瀏覧器之頁面図標、主画面図標及応用内標識者、共有 [`assets/brand/mascot-avatar.png`](../../assets/brand/mascot-avatar.png) 之吉祥物頭像也。其輸出尺寸者 `public/` 中存在: `logo.png` (512 px)、`favicon.png` (64 px)、及 `apple-touch-icon.png` (180 px)。各尺寸者再描画無用、由主図輸出也。

## 宿主外観統合

`SNOWLUMA_WEBUI_TARGET=maibot` 者、其部署可逆之 millennium 外観覆蓋層利用。単独運行之既定値者不変也。宿主者、不改個人設定、不加別選択器、実時明/暗更新反映可能也。変更目標起動、主題所有権、宿主消息伝達或範囲限定様式之前、[統合契約与拡張指南](INTEGRATIONS.md) 参照必要也。

## 操作規約

- 破壊性動作及二次確認者、模態対話框中実施也。
- 需時可能之操作者、右下表示実行中状態也。
- 完成及失敗之操作者、右下結果通知表示、可見倒數計時終了後自動閉合也。
- 日常之高頻調整者、中間編集毎通知発生無用也。
- 前景輪詢者、隠藏標籤頁中停止、各請求完成待機後次回予定也。接続状態輪詢者、SSE 客端購読中僅実行也。
- 資料依存之表面者、Interior Skeleton Swap 既定値（120 ms 遅延、380 ms 最小表示時間）使用、故本地高速応答不閃爍占位也。送出、上伝及其他明示操作之進捗者、仍以旋転指示器表示也。
- 可変高度内容者、準備完成後解放骨架確保之領域必要也。頁面内第二滾動領域導入無用也。
- 移動端導航菜単者、受控 Icon Morph 使用、其視覚状態追随実際抽屜状態也。
- 失敗者、影響控制項与操作結果両方可見保持必要也。失敗応答成功反饋変換無用也。
- JSON 端點者対象返却必要也。格式不良或非対象之応答者、空列表或既定設定表示而非、錯誤報告也。
- 設定応答含 `config`。保存時更報告 `saved`、`applied`、`online`、`errors`、`message`。UI 者此等字段使用、旧別名或保存後二次請求不依存也。
- 密碼変更流程者、浮動標籤与行内検証統一使用也。
- 密碼強度詳細者、新密碼欄聚焦中僅表示、聚焦離脱時同動態語言退場也。
- 初回向導者、同意文本為主要読取面保持、各歩驟操作単一応答式頁脚中整合也。設定含可見開発者頁面、安全再実行此向導、試行頁面級崩潰画面也。再実行之同意与密碼者永不保存也。

## 逆向代理背後之認証

已認証 WebUI 請求者、会話標記以 `X-SnowLuma-Token` 送出、故 `Authorization` 者逆向代理之 HTTP 認証（如 Nginx Basic Auth）可用也。代理過濾請求標頭之場合、`X-SnowLuma-Token` 不変転送必要也。後端者、専用標頭欠如時、既存客端向仍接受 `Authorization: Bearer <token>` 也。両層者各自有効憑証必要也。

旧会話之遅延認証失敗者、較新会話登出不致也。実時流者、断開時購読解放、頁面与共一時停止也。格式不良之流資料者報告也、調試流呼出者黙黙成功而非失敗也。

## 工程帳号検出

工程卡片者、注入前用 QQ 之本地帳号資料、登入後用鉤子確認之身分也。本地資料欠落者帳号不明意味也、QQ 已登出之証拠非也、僅本地検出者橋接上線標示永不也。手動登入探測与 `/api/processes/:pid/probe-login` 端點者削除也。

Linux 者、各 QQ 工程之 `XDG_CONFIG_HOME` 或 `HOME` 由資料根解決也。Windows 者、同梱插件之 `getFileHoldersAsync` 用、找持有各帳号資料庫之工程也。査詢失敗者、不当未登入、報告也。

## 帳号通知範本

Webhook 本体与郵件主題/本体者、`{uin}`、`{nickname}`、`{event}`（`offline` 或 `online`）、`{time}`、`{status}`（鉤子工程状態）、`{pid}`、及 `{error}`（鉤子工程錯誤）支持也。新 Webhook 与郵件通道者、既定本体含工程状態也、既存保存範本者保持也。JSON 範本者、含引号、換行及控制文字之置換字串転義也。

工程事実者、離線去抖之後、通知送出時解決也。各遷移者其工程 PID 携帯、含帳号離線時切離之最終 PID 也。事実者其 PID 与 UIN 検索、不致他工程代入也。欠落事実者空表示、不明意味、QQ 退出之証拠非也。鉤子状態僅者、QQ 登入失敗之原因特定不能也。一帳号之通知者遷移順配送也、遅帳号不遅延他帳号也。

## 本地開発

打包安裝者、設定 → About 中下載与再起動控制提供也。下載者検証与暫存也、文件者応用起動前適用也。再起動確認者共有模態框使用、下載結果者動作反饋使用也。

Windows 者、原生 API 起動時一度記録工程標記与 EXE 完整性標籤也。Low（或更低）標記者 WebUI 警告発動也、僅文件標籤与査詢失敗者不発動也。「临时关闭」者標籤頁会話中（含再読込）有効、「永久关闭」者此瀏覧器之站点儲存中持久也。両者起動記録抑制無也。失敗査詢与偏好書込者仍可見也。

倉庫根目録由:

```bash
pnpm --filter webui dev
pnpm --filter webui typecheck
pnpm --filter webui lint
pnpm --filter webui test
pnpm --filter webui build
```
