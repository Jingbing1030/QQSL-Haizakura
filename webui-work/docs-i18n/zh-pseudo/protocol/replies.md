# Reply 目標


通常之 OneBot `reply` 段者、非零符号付 `message_id` 依消息識別也。
負標識亦合法也。普通受信消息与送信結果之標識生成規則者不変也。

私聊 QQ 引用者、消息標識使用之会話序列而非、送信者本地序列使用可能性有也。
Haizakura 者会話、送信者方向、可用時標、引用文本保存済消息対照也。
異序列名空間之数値一致者、両記録同一消息指証拠為不可也。当前消息者自身之引用検索自除外也。

目標本地不可用時、実時事件処理者事件変換且分派前、上限付私聊履歴要求也。
検証済履歴消息者実際標識下保存、故即時之 `get_msg` 取得可能也。欠落本文補時、既存検証済標識保持、撤回済消息者復元無也。

未解決或曖昧之私聊目標者、推測標識或新置換記録生成無也。
通常事件者該 `reply` 段省略、消息之残余保持也。警告者未解決目標示、追跡記録者引用内容記録無、検索結果、会話、序列、時標、選択標識記録也。取得失敗者可視状態残留也。

群引用者群序列依検索維持也。転送節点者内聯引用内容保持、元消息本地帳号履歴中無場合尚再送可能也。

図像上伝者、下載参照与実際文件名永続消息元資料中保持也。`get_msg` 者各図像該消息自身之参照自更新、故文件名再使用或再起動依別上伝選択之事無也。

図像参照欠之古記録者、`get_msg` 保存済会話与序列（旧式私聊記録者保存済時標与客端序列）対上限付履歴要求也。
送信者、時刻、有序図像指紋一致之唯一消息仅欠落参照補可能也。修復者既存符号付 `message_id` 下保存、消息内容与識別元資料保持、請求保留中削除之記録復元事無也。
完全図像者履歴要求不要也。履歴不可用或一致検証不可場合、未検証図像資料者其儘残留且警告記録中記録也；下載 URL 推測之事無也。
