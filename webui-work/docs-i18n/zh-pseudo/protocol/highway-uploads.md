# 媒体転送設定


## 動画上伝接続数

動画上伝、既定一個接続使用也。**設定 → 全体構成 → 動画上伝接続数**於、一、二、三、
四之中選択接続数。`config/snowluma.json` 之同等設定如次。

```json
{
  "videoUploadConcurrency": 1
}
```

此設定、全帳号適用也。WebUI 之保存、次回動画上伝反映、既準備中或送信中之上伝、
原値保持。手動編集場合、Haizakura 再起動必要也。旧構成値欠落場合、一接続視也。
不正値、報告為、丸込無也。部分構成保存及構成備份、亦此設定保持。

並列化適用、動画本体僅也。封面、画像、音声消息、文件上伝、既存動作維持。
2 MiB 以下之動画、仍一接続使用。最終動画塊、先行全塊確認迄待機。此設定、
OneBot 動作、消息段、応答形状変更無也。

中断接続、上限有之再試行予算範囲内、未確認塊僅再試行。既知之伺服器背圧発生場合、
其上伝、一有効請求縮小、遅延後再試行。伺服器拒否、不正確認応答、再試行予算枯渇、
上伝失敗為。失敗上伝、送信済暗黙報告、決無也。

Debug 記録、動画準備及転送時間分別記録、要求並列度及実際並列度、接続数、再試行回数
報告。Trace 記録、塊毎試行、確認応答進捗、失敗状況含。並列度高無、特定速度保証無也。
性能判断前、缓存済上伝除外、同一文件及同一網条件比較必要。

回帰試験、分離伝輸使用、並列度上限、順序入替確認応答、途中停止先行塊、再試行枯渇、
背圧、清理対象為。此等試験、実際 QQ 配信及上伝吞吐量証明無也。

## 上伝超時及節点選択

全 Highway HTTP 上伝（画像、音声、動画、文件含）、各文件転送開始時、次之部署全体
環境変数快照為。

| 変数 | 既定値 | 意義 |
| --- | --- | --- |
| `SNOWLUMA_HIGHWAY_UPLOAD_IDLE_TIMEOUT_MS` | `30000` | 一回請求中、応答字節不到達状態之最大待機時間（毫秒）。応答字節到着時重置。 |
| `SNOWLUMA_HIGHWAY_UPLOAD_TIMEOUT_MS` | `1800000` | 一文件之転送予算合計（毫秒、三十分）。全塊、接続、書込、応答待機、再試行遅延共有。 |

例之、小画像送信部署、如次指定可能也。

```sh
SNOWLUMA_HIGHWAY_UPLOAD_IDLE_TIMEOUT_MS=5000
SNOWLUMA_HIGHWAY_UPLOAD_TIMEOUT_MS=120000
```

此等変数付、工程／容器再起動必要。両値、一乃至 2147483647 之整数必要也。不正値、
既定値暗黙使用而非、上伝可視失敗也。予算合計、塊成功後、受信字節到着後、別節点
切替時、亦重置無也。空閑計時器、HTTP 請求開始時（書込含）起動、低速接続、更大値
必要場合有。源流下載、摘要算、QQ 上伝準備、此転送予算之前実行也。動画本体及其封面、
別文件、別予算有也。

伝輸障害、未確認塊僅再試行。各塊、至少三回試行、或指定候選三以上場合、全異候選
網羅充分回数試行、文件予算合計条件許可也。各接続、三秒握手制限有。予算合計期限切
場合、全作業者中断、其接続閉鎖。未完了文件系統読取、源流閉鎖前排空、故清理、其期限
後完了可能也。伺服器明示拒否及不正確認応答、仍即座失敗。背圧再試行、別途上限設、
同一文件期限共有。

節点観測結果、帳号会話及上伝種別属、完全主機及端口為鍵。検証済成功上伝確認応答、
五分間優先。伝輸障害、其端点優先度三十秒間下。未知端点、直近失敗優先候選残、失敗
依候選恒久除外無也。選択可能、現在上伝指定宛先僅也。履歴、帳号会話毎最大百二十八
件観測結果保持、憑票及載荷含無、其帳号識別情報対象破棄時解放。工程再起動時消去。

TRACE 記録、実際適用超時及候選順序表示。読取超時、現在書込／読取段階、完了書込
字節数、受信字節数、応答標頭確認可否含。予算合計枯渇、別途 `upload_timeout` 報告。
失敗転送、失敗 OneBot 動作也。

## 媒体下載制限

二之部署全体設定値、`highway/utils.ts` 於 HTTP 媒体下載制限。此等、帳号単位 OneBot
設定而非環境変数也。全呼出元、同一下載引擎（`loadBinarySource` /
`stageSourceToDisk`）到達故也。

```sh
SNOWLUMA_HTTP_DOWNLOAD_TIMEOUT_MS=180000
SNOWLUMA_MAX_BINARY_DOWNLOAD_BYTES=2147483648
```

両者、以前硬編碼値既定、故未設定部署、以前全同動作也。不正値、記録無視、既定値
回退。既明示上限渡呼出元、其維持。集団／私密文件及閃伝転送、仍 4 GiB 使用、
内聯 `base64://` / `data:` 閃源、1 GiB 緩衝読込上限維持也。

`SNOWLUMA_HTTP_DOWNLOAD_TIMEOUT_MS`、`SNOWLUMA_DOWNLOAD_FILE_TIMEOUT_MS`
（`download_file` OneBot 動作使用）関係無也。前者 highway 媒体下載制限、後者其
動作自身文件予備置制限也。
