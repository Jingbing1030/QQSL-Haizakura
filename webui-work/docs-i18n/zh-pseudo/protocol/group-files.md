# 群文件送信与臨時保存


`upload_group_file` 与 `send_group_msg` 中之文件段、既定群永久文件空間使用也。
伺服器明示容量或文件数制限返却時、Haizakura 者一回臨時保存試、且記録中此切替記録也。
臨時申請、文件転送或聊天公開失敗者尚報錯也；権限不足、接続失敗等他之錯誤者切替触発無也。
臨時文件者期限切可能性有、永久保存之代替為不可也。

## 消息内容制限

臨時文件経路進入時、一消息者文件或図像段仅含可能也。
文字、提及、表情等他内容含之混合消息者拒否為、呼出側独立消息分割後送信必要也。
合併転送者各節点之内容依同一規則検査也。

Haizakura 者聊天消息公開前附件検査、不許可之組合発見時、先文字送、然後附件或文字棄之事無也。
検査前既完成之他附件上伝者自動削除無也。上伝成功後聊天公開失敗場合、錯誤尚文件標識保持也。
此複数消息跨之交易非也：公開開始後出現之網或伺服器側錯誤者、先行消息既到達可能性有也。

普通図像加文字者尚図像消息通道経由送信、群永久文件空間不足故群文件転変無也。
永久文件与文字之既存分離送信方式者互換保持也。超大動画者原有規則依文件転後、亦臨時文件之内容制限適用也。

## 文件再利用与下載

運行期間上伝済之群文件者、帳号、群、文件標識毎其保存類型保持也。
同群中 `file_id` 依再送信、下載鏈接取得或合併転送生成時、該保存類型使用也。
`get_group_file_url` 明示伝之 `busid` 尚優先也；有効値不提供時、当前会話記憶之類型使用、否則永久文件既定値沿也。
上伝記録者永続目録非也；再起動後臨時文件鏈接取得者、群文件列表自対応之 `busid` 取得且伝必要也。
