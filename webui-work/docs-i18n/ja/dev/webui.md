# Haizakura WebUI


Haizakura のブラウザコンソールは Vite + React アプリケーションであり、実行時の状態、OneBot の設定、ログ、ストレージ、サーバー設定を管理するためのものです。

## 既定の外観

新規インストールおよび外観のリセットでは、マスコットのラベンダー系アクセントを使用します。ライト版ではボタンのラベルを読みやすくするために濃い紫を、ダークモードではより淡いラベンダーを使用します。既存の保存済みアクセントとカスタムカラーは保持されます。元のスカイブルーのアクセントは設定から引き続き利用できます。

既定のパレットでは、ページ、カード、入力欄、ポップオーバー、サイドバーの各サーフェスが、ニュートラルなライト / ダークの背景に有効なアクセントを少量混ぜ込みます。テキストは可読性のためにニュートラルのままです。サイドバー専用のアクセントはサイドバーのみを着色し、OLED は真っ黒なキャンバスを維持します。名前付きパレット、カスタム CSS 変数、ホスト側の外観オーバーレイは、それぞれ自身のサーフェスの制御を保持します。

既定のアクセントを変更する際は、サーバー側の既定値を `packages/core/src/webui/ui-config.ts` に、フロントエンド側の既定値とプリセットを `src/contexts/ThemeContext.tsx` に、マウント前のトークンを `src/index.css` に、それぞれ揃えて保持してください。

ブラウザのファビコン、ホーム画面アイコン、アプリ内ロゴは、[`assets/brand/mascot-avatar.png`](../../assets/brand/mascot-avatar.png) のマスコットアバターを共有します。書き出されたサイズは `public/` にあり、`logo.png`（512 px）、`favicon.png`（64 px）、`apple-touch-icon.png`（180 px）です。個々のサイズを描き直すのではなく、マスターから書き出してください。

## ホストの外観連携

`SNOWLUMA_WEBUI_TARGET=maibot` を指定すると、そのデプロイは可逆な millennium 外観オーバーレイに参加します。スタンドアロンの既定値は変更されません。ホストは、個人の設定を上書きしたり別のセレクターを追加したりすることなく、ライト / ダークのライブ更新を駆動します。ターゲットの起動、テーマの所有権、ホストとのメッセージング、スコープ付きスタイルを変更する前に、[連携コントラクトと拡張ガイド](INTEGRATIONS.md) を参照してください。

## 操作の規約

- 破壊的な操作と二段階の確認は、モーダルダイアログ内にとどめます。
- 時間がかかる可能性のある操作は、右下に実行中の状態を表示します。
- 完了した操作と失敗した操作は、右下の結果通知を使用し、表示されるカウントダウンの後に自動的に閉じます。
- 日常的で頻度の高い調整では、中間の編集ごとに通知を生成しないようにします。
- フォアグラウンドのポーリングは、非表示のタブでは一時停止し、次のスケジュールを組む前に各リクエストの完了を待ちます。接続状態のポーリングは、SSE クライアントが購読している間のみ実行されます。
- データに基づくサーフェスは Interior Skeleton Swap の既定値（120 ms の遅延、380 ms の最小表示時間）を使用し、ローカルの高速な応答でプレースホルダーがちらつかないようにします。送信、アップロード、その他の明示的な操作の進捗は、自前のスピナーを維持します。
- 高さが可変のコンテンツは、準備ができた後にスケルトンが確保したボックスを解放する必要があります。ページ内に 2 つ目のスクロール領域を導入しないでください。
- モバイルのナビゲーションメニューは、視覚状態が実際のドロワー状態に追従する制御された Icon Morph を使用します。
- 失敗は、影響を受けたコントロール内と操作結果の両方に表示され続ける必要があります。失敗した応答を成功のフィードバックに変換しないでください。
- JSON エンドポイントはオブジェクトを返す必要があります。不正な形式の応答やオブジェクト以外の応答は、空のリストや既定の設定として表示するのではなく、エラーとして報告されます。
- 構成の応答には `config` が含まれます。保存時はさらに `saved`、`applied`、`online`、`errors`、`message` を報告します。UI はこれらのフィールドを、従来の別名や保存後の 2 回目のリクエストなしで使用します。
- パスワード変更のフローでは、フローティングラベルとインライン検証を一貫して使用します。
- パスワード強度の詳細は、新しいパスワードのフィールドがフォーカスを持っている間だけ表示され、フォーカスが外れると同じモーション言語で退場します。
- 初回起動ウィザードでは、同意文を主要な読み取り面として維持し、各ステップのアクションを 1 つのレスポンシブなフッター内に揃えます。設定には、このウィザードを安全に再実行し、ページレベルのクラッシュ画面を試すための、表示可能な開発者ページが含まれます。再実行された同意とパスワードは決して永続化されません。

## リバースプロキシ背後の認証

認証済みの WebUI リクエストは、セッショントークンを `X-SnowLuma-Token` で送信し、`Authorization` をリバースプロキシの HTTP 認証（Nginx Basic Auth など）のために空けておきます。プロキシがリクエストヘッダーをフィルタリングする場合は、`X-SnowLuma-Token` を変更せずに転送してください。バックエンドは、専用ヘッダーが存在しない場合、既存のクライアントのために `Authorization: Bearer <token>` を引き続き受け付けます。どちらの層も、それぞれ有効な資格情報を必要とします。

古いセッションからの遅延した認証失敗が、より新しいセッションをサインアウトさせることはありません。ライブストリームは、切断時に購読を解放し、ページとともに一時停止します。不正な形式のストリームデータは報告されます。デバッグ用のストリーム呼び出しは、黙って成功するのではなく失敗します。

## プロセスのアカウント検出

プロセスカードは、注入前は QQ のローカルアカウントデータを、ログイン後はフックが確認した身元を使用します。ローカルデータが欠落している場合は、アカウントが不明であることを意味します。これは QQ がサインアウトしていることの証明にはならず、ローカル検出だけでブリッジがオンラインとマークされることは決してありません。手動ログインプローブと `/api/processes/:pid/probe-login` エンドポイントは削除されました。

Linux では、各 QQ プロセスの `XDG_CONFIG_HOME` または `HOME` からデータルートを解決します。Windows では、同梱のアドオンの `getFileHoldersAsync` を使用して、各アカウントデータベースを保持しているプロセスを特定します。クエリの失敗は、未ログインとして扱うのではなく報告されます。

## アカウント通知テンプレート

Webhook の本文と、メールの件名 / 本文は、`{uin}`、`{nickname}`、`{event}`（`offline` または `online`）、`{time}`、`{status}`（Hook プロセスの状態）、`{pid}`、`{error}`（Hook プロセスのエラー）をサポートします。新しい Webhook チャネルとメールチャネルは、既定の本文にプロセスの状態を含みます。既存の保存済みテンプレートは保持されます。JSON テンプレートは、引用符、改行、制御文字を含む置換後の文字列をエスケープします。

プロセスの情報は、オフラインのデバウンスがある場合はその後に、通知がディスパッチされるときに解決されます。各遷移は自身のプロセス PID を保持し、アカウントがオフラインになったときに切り離される最後の PID も含みます。情報は、別のプロセスに置き換えることなく、その PID と UIN に対して検索されます。欠落した情報は空としてレンダリングされ、不明を意味し、QQ が終了したことの証明ではありません。Hook の状態だけでは、QQ のログイン失敗の原因を特定できません。1 つのアカウントの通知は遷移順に配信され、遅いアカウントが他のアカウントを遅延させることはありません。

## ローカル開発

パッケージ版のインストールでは、設定 → バージョン情報にダウンロードと再起動のコントロールがあります。ダウンロードは検証およびステージングされ、ファイルはアプリケーションの起動前に適用されます。再起動の確認は共有モーダルを使用し、ダウンロードの結果はアクションのフィードバックを使用します。

Windows では、ネイティブ API が起動時に一度だけプロセストークンと EXE の整合性ラベルをログに記録します。Low（またはそれ以下）のトークンは WebUI の警告を引き起こしますが、ファイルのラベルとクエリの失敗だけでは引き起こしません。「临时关闭」はタブのセッション中（再読み込みを含む）持続し、「永久关闭」はこのブラウザのサイトストレージに永続化されます。どちらも起動ログを抑制しません。失敗したクエリと設定の書き込みは表示され続けます。

リポジトリのルートから、次のように実行します。

```bash
pnpm --filter webui dev
pnpm --filter webui typecheck
pnpm --filter webui lint
pnpm --filter webui test
pnpm --filter webui build
```
