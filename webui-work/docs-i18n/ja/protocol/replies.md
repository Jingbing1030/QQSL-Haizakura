# Reply ターゲット


通常の OneBot `reply` セグメントは、非ゼロの符号付き `message_id` によってメッセージを識別します。
負の識別子も有効です。通常の受信メッセージと送信結果における識別子の生成規則は変わりません。

プライベート QQ の引用は、メッセージ識別子に使われる会話シーケンスではなく、送信者ローカルのシーケンスを使うことがあります。
Haizakura は会話、送信者の方向、利用可能なタイムスタンプ、引用テキストを保存済みメッセージと照合します。
異なるシーケンス名前空間の数値が一致したからといって、それだけで 2 つのレコードが同じメッセージを指す証拠にはなりません。現在のメッセージは自身の引用検索から除外されます。

ターゲットがローカルで利用できない場合、ライブイベント処理はイベントを変換・ディスパッチする前に、上限付きのプライベート履歴を要求します。
検証済みの履歴メッセージは実際の識別子の下に保存されるため、直後の `get_msg` で取得できます。欠落した本文を補う際、既存の検証済み識別子は保持され、撤回済みメッセージは復元されません。

未解決または曖昧なプライベートターゲットは、推測された識別子や新しいプレースホルダーレコードを生成しません。
通常のイベントはその `reply` セグメントを省略し、メッセージの残りを保持します。警告は未解決のターゲットを示し、トレースログは引用内容を記録せずに、検索結果、会話、シーケンス、タイムスタンプ、選択された識別子を記録します。取得の失敗は可視のまま残ります。

グループの引用はグループシーケンスによる検索を維持します。転送されたノードはインラインの引用内容を保持し、元のメッセージがローカルアカウントの履歴にない場合でも再送できます。

画像のアップロードは、ダウンロード参照と実際のファイル名を永続的なメッセージメタデータに保持します。`get_msg` は各画像をそのメッセージ自身の参照から更新するため、ファイル名の再利用や再起動によって別のアップロードが選ばれることはありません。

画像参照を欠く古いレコードについて、`get_msg` は保存された会話とシーケンス（旧式のプライベートレコードでは保存されたタイムスタンプとクライアントシーケンス）に対して上限付きの履歴を要求します。
送信者、時刻、順序付き画像フィンガープリントが一致する一意のメッセージのみが、欠落した参照を補えます。修復は既存の符号付き `message_id` の下に保存され、メッセージ内容と識別メタデータを保持し、リクエストが保留中に削除されたレコードを復元することはありません。
完全な画像には履歴要求は不要です。履歴が利用できない、または一致を検証できない場合、未検証の画像データはそのまま残され警告がログに記録されます。ダウンロード URL が推測されることはありません。
