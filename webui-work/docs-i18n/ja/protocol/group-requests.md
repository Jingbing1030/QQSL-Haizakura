# グループ招待と参加時の身元


メンバー A が B を招待し、管理者 C が承認する場合、招待者、参加者、処理者は 3 つの独立した身元です。
`group_increase.operator_id` を招待者とみなさないでください。また `sub_type: invite` だけから両者が同一だと推断しないでください。

## 参加通知

`group_increase` は既存の `user_id`、`operator_id`、`sub_type` を保持し、次を追加します。

| フィールド | 意味 |
| --- | --- |
| `invitor_id` | QQ が明示的に提供する独立した招待者の QQ 番号。特定できない場合は `0` |
| `invitor_status` | `known` は招待者の QQ 番号が判明していること、`unknown` は特定できないことを示す |

一部の承認参加プッシュは独立した招待者情報を提供し、Haizakura はそのプッシュから読み取って身元を解析します。
QR コード共有者は招待者とは別に扱われます。旧式のプッシュ、自身の参加通知、出所情報を欠く通知は `unknown` のままです。
同じグループ、同じメンバー、時刻の近さによって招待関係を推測することはなく、操作者で招待者を埋めることもありません。
身元照会の失敗はログに残り、参加イベントは既存の方針どおり報告され、招待者が不明でも通知は妨げられません。

## グループ申請リスト

`get_group_system_msg` が返す各レコードには次のフィールドが追加されます。

| フィールド | 意味 |
| --- | --- |
| `target_uin`、`target_nick` | 申請者または招待された参加者。常に B を表す |
| `operator_uin`、`operator_nick` | その申請を処理した操作者。承認の場面では C を表す |
| `target_status`、`invitor_status`、`operator_status` | 対応する QQ 番号が `known` か `unknown` か |

既存の `invitor_uin`、`invitor_nick` は A を表します。`requester_uin` は互換性を保ちます。通常の申請では申請者を表し、
ログイン中のアカウントを招待するレコードでは招待者を表します。三者を区別する必要がある場合は `target_uin`、`invitor_uin`、`operator_uin` を使ってください。
QQ が UID のみを提供する場合は対応する QQ 番号を照会し、照会は重複排除され並列度が制限されます。照会のエラーはインターフェースのエラーとして返され、空リストを装うことはありません。

```json
{
    "target_uin": 10002,
    "target_status": "known",
    "invitor_uin": 10004,
    "invitor_status": "known",
    "operator_uin": 10003,
    "operator_status": "known",
    "checked": true
}
```

**`0` や `unknown` は「招待者がいない」ことを意味しません。** QQ が身元を提供していない、レコードが見えない、身元がまだ解析されていない、といった場合はいずれも招待者がいないことの証明にはなりません。
現在確認済みのフィールドでは、欠落情報について「招待者なし」と確実に判断するには不十分であるため、そのような推測は出力しません。
同様に `checked: true` は処理済みであることだけを示し、必ず承認されたことを意味しません。`operator_uin` は拒否した人である可能性もあります。

`count` は各受信箱から読み取るレコード数を制限します（最大 100）。`group_id` は読み取り後に絞り込むものであり、
指定グループの完全な履歴を照会するものではありません。`only_pending` の既定は `false` です。空配列は今回の読み取り範囲に一致するレコードがないことを示すだけで、
ある参加に招待者がいなかったことの証明にはなりません。デバッグログは受信箱の件数、種別による絞り込み、最終的な絞り込み件数をそれぞれ記録します。

SDK の `getGroupSystemMessages()` は対応する型を提供します。追加されたフィールドは旧サーバーとの互換性のため SDK では任意です。
旧サーバーへ接続した場合、欠落した状態も不明として扱うべきです。
