# グループファイルの送信と一時ストレージ


`upload_group_file` と `send_group_msg` のファイルセグメントは、既定ではグループの永久ファイル空間を使います。
サーバーが容量またはファイル数の制限を明示的に返した場合、Haizakura は一度だけ一時ストレージを試し、その切り替えをログに記録します。
一時的な申請、ファイル転送、チャットへの公開に失敗した場合は引き続きエラーとなりますが、権限不足や接続失敗などその他のエラーでは切り替えは発生しません。
一時ファイルは期限切れになる可能性があり、永久保存の代替にはできません。

## メッセージ内容の制限

一時ファイルの経路に入ると、1 つのメッセージに含められるのはファイルセグメントまたは画像セグメントのみです。
テキスト、メンション、絵文字などを含む混合メッセージは拒否されるため、呼び出し側が独立したメッセージに分割してから送信する必要があります。
結合転送は各ノードの内容について同じ規則で検査されます。

Haizakura はチャットメッセージを公開する前に添付を検査し、許可されない組み合わせを検出した場合、先にテキストを送ってから添付やテキストを捨てることはしません。
検査より前に完了した他の添付のアップロードは自動的に削除されません。アップロード成功後にチャットへの公開が失敗した場合も、エラーにはファイル識別子が保持されます。
これは複数メッセージにまたがるトランザクションではありません。公開を開始した後に発生したネットワークやサーバー側のエラーでは、先行するメッセージがすでに届いている可能性があります。

通常の画像 + テキストは引き続き画像メッセージの経路で送信され、グループの永久ファイル空間が不足してもグループファイルへ切り替わることはありません。
永久ファイルとテキストを分けて送る既存の方式との互換性は維持されます。極端に大きな動画は従来の規則でファイルに変換された後、一時ファイルの内容制限も適用されます。

## ファイルの再利用とダウンロード

実行中にアップロードしたグループファイルは、アカウント、グループ、ファイル識別子ごとにそのストレージ種別が保持されます。
同じグループ内で `file_id` を使って再度送信する場合、ダウンロードリンクを取得する場合、結合転送を生成する場合は、このストレージ種別が使われます。
`get_group_file_url` に明示的に渡した `busid` は引き続き優先されます。有効な値が提供されない場合は、現在のセッションが記憶している種別を使い、それもなければ永久ファイルの既定値に従います。
アップロードの記録は永続的なディレクトリではありません。再起動後に一時ファイルのリンクを取得する場合は、グループファイル一覧から対応する `busid` を取得して渡してください。
