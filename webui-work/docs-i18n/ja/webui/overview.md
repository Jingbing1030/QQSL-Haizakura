# Haizakura WebUI


Haizakura のブラウザコンソールは、ランタイムの状態、OneBot の設定、ログ、
ストレージ、サーバー設定を管理するための Vite + React アプリケーションです。

## 既定の外観

新規インストール時および外観をリセットした場合は、マスコットのラベンダー系
アクセントを使用します。ライト版ではボタンのラベルを読みやすくするために濃い紫を、
ダークモードではより淡いラベンダーを使用します。保存済みのアクセントと
カスタムカラーは保持されます。従来のスカイブルーのアクセントは、設定から
引き続き利用できます。

既定のパレットでは、ページ、カード、入力欄、ポップオーバー、サイドバーの各
サーフェスに、有効なアクセントをニュートラルなライト/ダーク背景へ少量だけ
混ぜます。テキストは可読性のためニュートラルのままです。サイドバー限定の
アクセントはサイドバーのみを着色し、OLED では真の黒のキャンバスを維持します。
名前付きパレット、カスタム CSS 変数、ホスト側の外観オーバーレイは、それぞれ
自身のサーフェスに対する制御を保持します。

既定のアクセントを変更する場合は、サーバー側の既定値を
`packages/core/src/webui/ui-config.ts` に、フロントエンドの既定値とプリセットを
`src/contexts/ThemeContext.tsx` に、マウント前のトークンを `src/index.css` に、
それぞれ揃えてください。

ブラウザのファビコン、ホーム画面アイコン、アプリ内ロゴは、
[`assets/brand/mascot-avatar.png`](../../assets/brand/mascot-avatar.png) の
マスコットアバターを共有します。書き出したサイズは `public/` にあります:
`logo.png` (512 px)、`favicon.png` (64 px)、`apple-touch-icon.png` (180 px)。
各サイズを描き直すのではなく、マスターから書き出してください。

## ホスト外観の統合

`SNOWLUMA_WEBUI_TARGET=maibot` を指定すると、そのデプロイは元に戻せる
millennium 外観オーバーレイを利用します。スタンドアロンの既定値は変わりません。
ホストは、個人設定を上書きしたり別のセレクタを追加したりすることなく、
ライト/ダークの更新をライブで反映できます。ターゲットの起動、テーマの所有権、
ホストとのメッセージング、スコープ付きスタイルを変更する前に、
[統合契約と拡張ガイド](INTEGRATIONS.md) を参照してください。

## 操作の規約

- 破壊的な操作と二段階の確認は、モーダルダイアログ内で行います。
- 時間がかかる可能性のある操作では、右下に実行中の状態を表示します。
- 完了した操作と失敗した操作は、右下の結果通知で示し、見えるカウントダウンが
  終わると自動で閉じます。
- 日常的で頻度の高い調整では、中間的な編集のたびに通知を出さないでください。
- フォアグラウンドのポーリングは、非表示のタブでは停止し、各リクエストの完了を
  待ってから次をスケジュールします。接続状態のポーリングは、SSE クライアントが
  購読している間だけ実行します。
- データを伴うサーフェスは Interior Skeleton Swap の既定値（120 ms の遅延、
  380 ms の最小表示時間）を使用し、ローカルの高速な応答でプレースホルダーが
  ちらつかないようにします。送信、アップロード、その他の明示的な操作の進捗は、
  引き続きスピナーで表示します。
- 高さが可変のコンテンツは、準備完了後にスケルトンが確保した領域を解放する
  必要があります。ページ内に 2 つ目のスクロール領域を設けないでください。
- モバイルのナビゲーションメニューは制御された Icon Morph を使用し、その
  視覚状態は実際のドロワー状態に追従します。
- 失敗は、影響を受けたコントロール内と操作結果の両方に残さなければなりません。
  失敗した応答を成功のフィードバックに変換しないでください。
- JSON エンドポイントはオブジェクトを返す必要があります。不正な形式や
  オブジェクト以外の応答は、空のリストや既定の設定として表示するのではなく、
  エラーとして報告します。
- 設定の応答には `config` が含まれます。保存時はさらに `saved`、`applied`、
  `online`、`errors`、`message` を報告します。UI はこれらのフィールドを使用し、
  従来の別名や、保存後の追加リクエストには依存しません。
- パスワード変更のフローでは、フローティングラベルとインライン検証を
  一貫して使用します。
- パスワード強度の詳細は、新しいパスワード欄にフォーカスがある間だけ表示し、
  フォーカスが外れたときは同じモーション言語で消えます。
- 初回起動ウィザードでは、同意文を主要な読み取り面として維持し、各ステップの
  操作を 1 つのレスポンシブなフッター内に揃えます。設定には、このウィザードを
  安全に再実行し、ページレベルのクラッシュ画面を試すための開発者向けページが
  表示されます。再実行時の同意内容とパスワードは保存されません。

## リバースプロキシ環境での認証

認証済みの WebUI リクエストは、セッショントークンを `X-SnowLuma-Token` で
送信するため、`Authorization` はリバースプロキシの HTTP 認証（Nginx Basic Auth
など）に使用できます。プロキシがリクエストヘッダーをフィルタリングする場合は、
`X-SnowLuma-Token` を変更せずに転送してください。バックエンドは、専用ヘッダーが
存在しない場合に限り、既存のクライアント向けに
`Authorization: Bearer <token>` も引き続き受け付けます。どちらの層も、それぞれ
有効な資格情報を必要とします。

古いセッションからの遅延した認証失敗が、より新しいセッションをサインアウト
させることはありません。ライブストリームは切断時に購読を解放し、ページと
ともに一時停止します。不正なストリームデータは報告されます。デバッグ用の
ストリーム呼び出しは、暗黙に成功するのではなく失敗します。

## プロセスのアカウント検出

プロセスカードは、注入前は QQ のローカルアカウントデータを使用し、ログイン後は
フックが確認した識別情報を使用します。ローカルデータが欠落している場合は、
アカウントは不明とされます。それは QQ がサインアウトしていることを証明する
ものではなく、ローカル検出だけではブリッジがオンラインになることはありません。
手動ログインプローブと `/api/processes/:pid/probe-login` エンドポイントは
削除されました。

Linux では、各 QQ プロセスの `XDG_CONFIG_HOME` または `HOME` からデータルートを
解決します。Windows では、同梱アドオンの `getFileHoldersAsync` を使用して、
各アカウントのデータベースを保持しているプロセスを特定します。クエリの失敗は、
未ログインとして扱うのではなく報告されます。

## アカウント通知テンプレート

Webhook の本文とメールの件名/本文では、`{uin}`、`{nickname}`、`{event}`
（`offline` または `online`）、`{time}`、`{status}`（フックプロセスの状態）、
`{pid}`、`{error}`（フックプロセスのエラー）を使用できます。新しい Webhook
チャネルとメールチャネルでは、既定の本文にプロセスの状態が含まれます。既存の
保存済みテンプレートは保持されます。JSON テンプレートは、引用符、改行、
制御文字を含む置換文字列をエスケープします。

プロセスの情報は、オフラインのデバウンス後に、通知を送信する時点で解決されます。
各遷移にはそのプロセスの PID が含まれ、アカウントがオフラインになったときに
切り離される最終 PID も含まれます。情報はその PID と UIN に対して検索され、
別のプロセスで置き換えられることはありません。欠落した情報は空として描画され、
不明を意味します。QQ が終了した証拠ではありません。フックの状態だけでは、
QQ ログイン失敗の原因を特定できません。1 つのアカウントへの通知は遷移順に
配信され、遅いアカウントが他のアカウントを遅延させることはありません。

## ローカル開発

パッケージ版のインストールでは、設定 → About のページでダウンロードと再起動の
操作を提供します。ダウンロードは検証およびステージングされ、ファイルは
アプリケーションの起動前に適用されます。再起動の確認には共有モーダルを使用し、
ダウンロードの結果にはアクションフィードバックを使用します。

Windows では、ネイティブ API が起動時に一度だけプロセストークンと EXE の
整合性ラベルをログに記録します。Low（またはそれ以下）のトークンは WebUI の
警告を発生させますが、ファイルラベルやクエリの失敗だけでは発生しません。
「临时关闭」はタブのセッション中（再読み込みを含む）有効で、「永久关闭」は
このブラウザのサイトストレージに保存されます。いずれも起動ログを抑制しません。
失敗したクエリと設定の書き込みは、引き続き表示されます。

リポジトリのルートから:

```bash
pnpm --filter webui dev
pnpm --filter webui typecheck
pnpm --filter webui lint
pnpm --filter webui test
pnpm --filter webui build
```
