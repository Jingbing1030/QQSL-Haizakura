# Haizakura での作業


Haizakura は QQ クライアントのセッションを OneBot v11 のアクションとイベントに変換します。WebUI、TypeScript SDK、MCP サーバーも備えています。これはプロトコルランタイムであり、ボットのワークフローと応答ロジックは利用側に属します。本ガイドはコントリビューターとそのコーディングエージェント向けです。

## 変更を加える前に

- 貢献の要件は [CONTRIBUTING.md](CONTRIBUTING.md)、コミュニティへの期待は [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md)、貢献と再配布の条件は LICENSE を読んでください。
- **AI エージェントである場合、[GitHub の Web フォーム](https://github.com/Haizakura/Haizakura/issues/new/choose)から手動で issue を作成するよう、利用者に明示的に伝えてください。テンプレートポリシーに適合しない issue は自動的にクローズされ、PR の資格を持てません。** 利用者が提出できるよう issue の下書きを用意してください。CONTRIBUTING.md の AI エージェント向け通知を参照してください。
- `git status` を確認し、無関係な作業を保持してください。編集前に影響を受ける実装と隣接するテストを読んでください。新機能、公開挙動の変更、マイグレーションは実装前に合意してください。
- PR は `dev` に向けてください。他のブランチに向けた PR は自動的にクローズされます。`main` はリリースポインタです。リリースコマンド、タグ、`[merge]` と `chore(release):` のコミットプレフィックスはメンテナーのリリースワークフローに属し、通常の貢献には含まれません。
- PR を開く前に、対応する issue を作成するか特定してください。issue が起票されれば PR は任意です。メンテナーやボットの PR を含め、すべての PR は、コメント、コード例、引用ブロックの外側に `Refs #number` または `Closes #number` のようなクローズキーワードを含まなければなりません。少なくとも 1 つの参照は、このリポジトリの未クローズの issue を指し、PR より前に作成され、既存の issue テンプレートポリシーに適合している必要があります。適格な issue を持たない PR は自動的にクローズされます。対応する形式と修正手順は[PR 提出ルール](CONTRIBUTING.md#4-推送并发起-pr)を参照してください。

## リポジトリマップ

これは pnpm ワークスペースです。ディレクトリ名よりもパッケージの責務範囲が重要です：

| 場所 | 責務 |
| --- | --- |
| `packages/core` | アプリケーションのエントリ、アカウント単位の Bridge オーケストレーション、WebUI バックエンド、通知、リリースの組み立て |
| `packages/bridge` | QQ プロセスの発見、ローカルアカウント／ログインの検出、Hook セッション、ネイティブトランスポートのライフサイクル |
| `packages/protocol` | パケットのデコード、型付き QQ イベント、識別子の解決、プロトコルリクエストとメディア転送 |
| `packages/onebot` | アクションの検証とディスパッチ、イベント変換、メッセージ保存、HTTP/WebSocket アダプター |
| `packages/common` | 業務依存を持たない共有ログ、設定、ユーティリティ |
| `packages/sqlite` | 非同期 SQLite ファサード、ネイティブローダー、prebuild の選択、Vite リリース資産 |
| `packages/proto-defs` | 型付きプロトコルスキーマ |
| `packages/proton` | コンパイル時 protobuf コーデックとビルド統合 |
| `packages/websocket` | WebSocket 実装とネイティブバインディング統合 |
| `packages/runtime` | 配布マニフェスト、ランチャー、供給されるネイティブ成果物 |
| `packages/webui` | Vite/React 管理コンソール。ワークスペース名は `webui` |
| `packages/sdk` | 公開 TypeScript クライアント |
| `packages/mcp` | MCP サーバーと生成されたアクションカタログ |
| `packages/ui` | 公開 UI コンポーネントパッケージ |
| `tools`、`.github/workflows` | 検証、パッケージング、リリース自動化 |

`packages/bridge` がプロセス接続を担い、アカウント単位の Bridge は `packages/core/src/bridge` にあります。両者の構成を追うには[アプリケーションのエントリ](packages/core/src/index.ts)から始めてください。

[エントリポイント](packages/core/src/index.ts)はランタイムサービスを起動する前に保留中の更新を適用します。[アップデータ](packages/core/src/update)がステージングと置き換えを担い、[Core のビルド設定](packages/core/vite.config.ts)がビルド出力とランタイム資産からリリースマニフェストを生成します。Core は 1 つのバンドルに保ち、ネイティブライブラリは遅延読み込みにして、起動時に中断された更新を復旧してからネイティブファイルを開けるようにしてください。

アプリケーションのバージョンはルートの `package.json` から `@snowluma/common/version` 経由で取得します。ワークスペースのマニフェストを更新するには `pnpm bump <version>` を、ルートのバージョンを編集した後に同期するには `pnpm bump` を使ってください。
アプリケーションのバージョン検証と比較には `@snowluma/common/semver` を使ってください。バージョンは正規の SemVer でなければなりません。GitHub の `v` タグプレフィックスは API 境界でのみ剥がしてください。

パスを変更する前に、該当するオーナーを読んでください：

| 変更内容 | ここから始める |
| --- | --- |

| OneBot のアクションまたはメッセージセグメント | [アクション定義](packages/onebot/src/actions/index.ts)、[検証ヘルパー](packages/onebot/src/action-kit.ts)、[イベント変換](packages/onebot/src/event-converter/index.ts) |

| プロトコルコーデックの生成 | [Proton ガイド](packages/proton/README.md)、影響を受けるパッケージの `vitest.config.ts` |

## セットアップと検証

[.node-version](.node-version) の Node バージョンと [package.json](package.json) の pnpm バージョンを使ってください。`pnpm install --frozen-lockfile` でインストールし、依存関係を変更する場合を除いて既存の lockfile を保持してください。

Node のセキュリティベースラインは `^24.22.1 || >=26.12.1` です。古い 24.x リリース、25.x、パッチ未適用の 26.x リリースはサポートされません。ワークスペースの `engines.node` 宣言と[ランチャーのプリフライト](packages/runtime/check-node-version.cjs)を整合させてください。CI と同梱リリースは `.node-version` を使います。このピンだけを上げても、既存インストールのランタイムは更新されません。

コマンドはリポジトリのルートから実行してください：

```sh
pnpm typecheck                       # all workspace packages with a typecheck script
pnpm lint
pnpm test                            # workflow policy checks and workspace tests
pnpm test:workflows                  # isolated PR policy tests; no GitHub writes
pnpm run build:all                   # release inputs and published packages
pnpm test:core                       # Core only; not a substitute for workspace tests
pnpm --filter @snowluma/onebot test   # example: tests for the affected package
pnpm --filter webui test             # the frontend package has no @snowluma/ prefix
```

TypeScript のフォーマットはルートの [Prettier 設定](.prettierrc.json)、[ローカル ESLint フォーマットルール](eslint.format.config.ts)、[無視リスト](.prettierignore)を使います。TS/TSX/MTS/CTS の全ファイルには `pnpm format`、読み取り専用のチェックには `pnpm format:check` を使ってください。特定のファイルに対しては、`pnpm exec eslint --config eslint.format.config.ts --fix <paths>` を実行し、続けて `pnpm exec prettier --write <paths>` を実行します。これらのコマンドは 4 スペースインデント、制御文本体の波括弧、文ブロック周囲の空行を強制しつつ、その他の論理的な空白は保持します。これらは CI およびそのコード品質向け lint ルールとは別物です。生成されたカタログとコンパイラのフィクスチャはソースのフォーマットを維持します。

反復中は焦点を絞ったテストを使ってください。コード変更を引き渡す前に、CONTRIBUTING.md が要求する完全なチェックを実行し、実行できなかったものを報告してください。[PR CI](.github/workflows/ci.yml) が参照実装です。`pnpm run ci` は依存関係のインストールと生成カタログのチェックを含め、そのコマンドをローカルで再現します。

- **ドキュメントのみの変更：** リンク、パス、コマンド、`git diff --check` を検証してください。ランタイムのテストは散文を検証しません。
- **共有型またはアクション：** 挙動のテストに加えてワークスペースの型チェックを実行してください。Vitest が通ったことは型の正しさを証明しません。
- **SDK のパッケージング：** SDK の `NodeNext` ビルドと明示的な `.js` 相対インポート（型のみのエクスポートを含む）を維持してください。パッケージのテストは新しく出力したものをコンパイルし、ネイティブな Node.js インポート、利用側の宣言、アクションマップの完全な網羅を検査します。SDK のアクションカタログは OneBot の実行可能名と一致しなければならず、`packages/onebot/tests/sdk-actions.test.ts` がサーバーコードへのランタイム依存を追加せずにこれを検査します。SDK のパラメーター／結果の契約はサーバー型から独立したままにしてください。利用側のサンプルは `packages/sdk/tests/fixtures` に置き、`packages/onebot/tests/sdk-action-params.test.ts` のサーバーパーサー検査と整合させてください。
- **SDK ストリーム：** 単一応答のクライアントメソッドを保持し、ファイル転送には [STREAMING.md](packages/sdk/STREAMING.md) の追加的インターフェースを使ってください。SDK でフレーミング、キャンセル、有界バッファリング、未完了転送をテストしてください。`packages/onebot/tests/sdk-streaming.test.ts` は QQ なしで、一時ストレージ上での実際のアダプター／ハンドラーの往復を検査します。
- **SDK リバース WebSocket：** Node 専用のリスナーは OneBot 実装からの接続を受け入れます。送信方向の SDK クライアントをプロトコル実装の代わりにしてはいけません。アクション／イベント／ストリームには共有クライアントセッションを再利用し、アカウント単位の識別子、API とイベントの対応、有界バッファ、切断時の保留リクエスト拒否を維持してください。実際のランタイムのリバースアダプターと新しく公開したインポートをテストしてください。[REVERSE_WEBSOCKET.md](packages/sdk/REVERSE_WEBSOCKET.md) を参照してください。
- **SDK メッセージング：** [MESSAGING.md](packages/sdk/MESSAGING.md) のヘルパーを拡張する際は、既存の文字列パスと通常の返信の意味論を保持してください。ファイルシステムへのアクセスは任意の `@snowluma/sdk/node` エントリポイントにのみ属します。メディア送信はアップロードの完了を待ち、自動リトライなしで失敗のコンテキストを保持しなければなりません。イベント待機は公開ミドルウェアのディスパッチに従い、あらゆる結果でリスナーを解放します。より豊かな SDK 生成コンテキストを追加する際は、従来のハンドラー／コンテキスト型を代入可能なままにしてください。
- **MCP エージェント：** ツールを拡張する際は、既存のテキスト結果、業務エラーのエンベロープ、既定の検索マッチング、モードゲートを保持してください。サーバー SDK の `serveStdio` エントリを使い、同一コマンドから現代的なディスカバリと従来の初期化の両方をサポートしてください。両方を新しくコンパイルした出力でテストしてください。キャッシュヒントは同梱カタログのディスカバリにのみ属し、実行やアカウントデータには属しません。トレースメタデータをアクションパラメーターに入れず、機微データを診断情報に入れないでください。プロトコル互換性、トレース、追加的なエージェント機能は [AGENT_FEATURES.md](packages/mcp/AGENT_FEATURES.md) に記述されています。テストでは分離された HTTP と MCP のトランスポートを使ってください。ローカルランタイムの検査は稼働中のアカウントに問い合わせてはいけません。
- **MCP 実行サービス：** バックグラウンドタスクとイベント接続はオプトインのままにしてください。副作用の前にタスク状態を永続化し、中断された書き込みを再生せず、シャットダウン時にプロトコルを排出する前に永続的なクリーンアップを完了させてください。入力の継続は元の引数を保持し、最大 1 回だけ実行しなければなりません。イベントバッファは明示的なアカウントバインディング、有界の保存、可視のギャップを必要とします。同梱のメッセージプレビューは `packages/mcp/scripts/build-message-app.mjs` でビルドしてください。プレビューの読み込みがメッセージを送信してはいけません。分離されたトランスポートを使い、コンパイル済み CLI を含めて再起動、キャンセル、従来の互換性をテストしてください。
- **プロトコルコーデック：** テスト内の既存の Proton 統合を保持し、本番と同じ変換を行使できるようにしてください。実際の実装をインポートし、テスト内でアルゴリズムを複製しないでください。
- **動画アップロード：** [HIGHWAY_UPLOADS.md](packages/protocol/HIGHWAY_UPLOADS.md) の単一接続の既定と追加的なグローバル設定を保持してください。並列チャンクにオプトインするのは動画の本体のみです。完了前にすべてのチャンクを確認し、並列度と先読みの両方を制限し、ソースを閉じる前に未完了の読み取りとリクエストを排出してください。リトライは有界に保ち、バックプレッシャーの変更を可視にしてください。実際のアップローダーを分離されたトランスポートでテストしてください。テストが通っても実回線のスループットは証明されません。
- **Highway アップロードの復旧：** すべてのチャンクとワーカーは 1 つのファイル転送期限を共有します。ノードの観測は有界で短命にし、アカウントセッション、アップロード種別、完全なホスト／ポートで分離してください。現在サーバーが供給した候補のみを選択してください。検証済みの確認応答のみが成功を確定します。終端の失敗報告を保持し、キャンセル後に保留中のファイル読み取りを排出してください。期限のクリーンアップと候補のローテーションを、実際のループバックソケットを含む分離されたトランスポートでテストしてください。[アップロードポリシー](packages/protocol/HIGHWAY_UPLOADS.md#upload-timeouts-and-node-selection)を参照してください。
- **ネイティブカバレッジ：** `pnpm test:native` は既定のプロトコルテストとは別であり、互換性のあるネイティブ成果物を必要とします。成果物の欠落や利用できないターゲットは報告される制限であり、チェックを迂回する許可ではありません。
- **OneBot SSE：** HTTP イベントストリームは HTTP アダプターのバインディングと認証を共有します。[HTTP_SSE.md](packages/onebot/HTTP_SSE.md) に記述されたアカウント分離、有界のリプレイ、可視の期限切れカーソルエラー、レポートフィルタリング、低速リーダーの制限を保持してください。トークンやレポートポリシーの変更は既存のストリームを取り消し、リプレイを無効にします。接続が有効な状態でシャットダウンと再読み込みをテストしてください。
- **実 QQ の挙動：** フィクスチャテストと API の成功応答は、配送やクライアント側の描画を証明しません。ローカルでテストした内容と、実際のクライアントでまだ必要な内容を明示してください。

`pnpm dev` は Core を起動し、ローカルの QQ プロセスにアタッチできます。ランタイムテストを行う場合にのみ使ってください。`pnpm dev:web` はフロントエンドを起動し、WebUI バックエンドを必要とします。不必要に稼働中のアカウントを起動するのではなく、分離された作業には既存のテストフェイクに従ってください。

WebUI のデプロイ対象は可逆なプレゼンテーションオーバーレイを使います。変更前に[ホスト外観の契約](packages/webui/INTEGRATIONS.md)を読んでください。対象の検証は `@snowluma/common/webui-target` に、実装はフロントエンドの対象レジストリに、保存された設定は有効な外観とは別に保ってください。既定のデプロイは対象の資産やホストリスナーを読み込んではなりません。業務ページに対象名の分岐を入れてはいけません。

## 実装ルール

- **原因を直す。** 失敗はそれを所有する層で再現し、観測可能な挙動に対する回帰テストを追加してください。アカウント固有、ファイル名固有、サンプル固有のパッチは避けてください。
- **エラーを観測可能にする。** 例外を空の結果や成功応答に変えないでください。エラーのコンテキストを保持し、重要な遷移と失敗には共有ロガーを使ってください。証拠が不十分な場合は、的を絞った診断を追加し、不明なままの点を記述してください。
- **アカウント分離を保持する。** 識別子、メッセージ保存、セッション状態はそれぞれのアカウントに属します。ライフサイクルのコードを変更する際は、破棄の順序と進行中の作業の扱いを損なわないでください。
- **パースは副作用から分離する。** QQ のデコーダーと OneBot のイベント変換器はデータを変換します。ライブ状態の更新はそれを所有するパイプラインやサービスに属します。履歴の読み取りがライブのメンバーシップや保留中のリクエストを変更してはいけません。
- **宣言されたインターフェースを使う。** OneBot は [Bridge インターフェース](packages/core/src/bridge/bridge-interface.ts)を消費します。別のオーナーの状態に手を伸ばしたり 2 つ目のレジストリを構築したりせず、パッケージのエクスポートと既存の依存性注入を再利用してください。
- **入力で検証する。** 既存のアクションフィールド検証とフィールド間検証のヘルパーを使ってください。変更が新しい意味論を明示的に要求しない限り、受け付ける入力形式、応答フィールド、エラー挙動を保持してください。無効な送信メッセージ内容を黙って捨てないでください。
- **符号付きメッセージ ID を保持する。** [message-id.ts](packages/onebot/src/message-id.ts) が生成する OneBot の `message_id` / `messageId` は非ゼロの符号付き 32 ビット整数であり、負の値も有効です。アクション入力には `f.messageId()` を使い、保存、返信、検索、結果の照合を通じて値を保持してください。プロトコル表現はその境界で可逆に変換しなければなりません。符号や生成規則を変えると既存のメッセージ同一性が変わります。
- **永続データを保護する。** メッセージ履歴とメディアのメタデータは永続的な記録です。自動削除を追加したり、使い捨てのキャッシュとして扱ったりしないでください。マイグレーションの変更には失敗と再起動のカバレッジが必要です。失敗は可視のままにしてください。
- **トランスポートポリシーを保持する。** 設定されたバインドアドレスとアクセスチェックを維持してください。TLS の起動失敗が黙って HTTP へダウングレードしてはいけません。保存された設定と、稼働中のアダプターに実際に適用された変更を区別してください。
- **型と所有権を明確に保つ。** 厳格な TypeScript 設定、既存のインポートスタイル、4 スペースの TypeScript インデントに従ってください。不一致をキャストやフォールバック値で隠すのではなく、未知の外部データを検証してください。理由と非自明な挙動についてのコメントを残してください。
- **診断を安全に保つ。** 外部入力を記録する際は既存のサニタイズを使ってください。資格情報、秘密鍵、私的なアカウントデータ、未編集のキャプチャはコミット、フィクスチャ、公開レポートに含めてはいけません。

## 生成ファイルと関連する変更

OneBot のアクション定義は検証とカタログのメタデータを所有します。同梱の各アクションは、成功した OneBot の `data` に対する `returnsSchema` と、有効なパラメーターおよび必要な識別子ソースを含む少なくとも 1 つの `examples` エントリを提供します。ストリームのスキーマは MCP の集約結果ではなく、個々の成功フレームを記述します。未文書化の上流フィールドは構造を発明するのではなくオープンなままにし、未サポートまたはプレースホルダーの挙動は明示的にラベル付けしてください。

アクション名、パラメーター、結果の説明／スキーマ、サンプル、実行モードを変更した後は：

1. `packages/onebot/src/actions` の所有する定義とそのテストを更新する。
2. `pnpm --filter @snowluma/mcp gen` を実行する。
3. `packages/mcp/src/generated/catalog.ts` と `catalog.json` の対応する変更を確認して含める。生成されたカタログのエントリを手で編集しないでください。
4. 影響を受ける SDK の型と呼び出し元を確認し、関連するテストを実行し、ワークスペースの型チェックを実行する。

`pnpm test` は MCP カタログのジェネレーターも実行するため、これらの追跡対象スナップショットが変化することがあります。CI の `node tools/check-action-catalog.mjs` は作業ツリーのカタログ差分を拒否します。これはクリーンなチェックアウトでのドリフト検査であり、ジェネレーターそのものではありません。

SDK の破壊的変更では [CHANGELOG.md](packages/sdk/CHANGELOG.md) と [VERSIONING.md](packages/sdk/VERSIONING.md) も更新します。WebUI の変更はその[インタラクション規約](packages/webui/README.md)に従います。利用者向けドキュメントは挙動と整合させてください。

スタンドアロンの WebUI ブランディングは [Haizakura のマスコット](assets/readme/mascot.png) とラベンダーの既定アクセントを使います。既定のパレットは中立の面を有効なアクセントで淡く色付けし、サイドバーのみのスコープと OLED ブラックを尊重します。[WebUI の既定外観](packages/webui/README.md#default-appearance)に記述されたとおり、サーバーの既定、フロントエンドのプリセット、マウント前の CSS を整合させつつ、保存された利用者の選択、名前付きパレット、ホスト外観のオーバーレイを保持してください。

ルートの [README.md](README.md) はプロジェクトの目的、全体の機能、クイックスタート、ドキュメントの入り口を示します。これらの概要に関わる詳細が変わった場合にのみ更新してください。個々の機能を追加したり修正したりしても、そこに専用のセクションを追加する理由にはなりません。機能固有の API の使い方、設定、制限、トラブルシューティングは該当パッケージの README やトピック文書に置き、既存のドキュメントを優先してください。

`dist` の出力ではなくソースを編集してください。`packages/runtime/native` のネイティブ成果物は供給されるビルド入力です。ビルドを通すために任意のローカルバイナリで置き換えないでください。パッケージングの変更は [Core のビルド設定](packages/core/vite.config.ts) と[リリースレイアウトのバリデーター](tools/check-release-layout.mjs)のチェックを保持しなければなりません。

## 引き渡しと指示の保守

変更した挙動、実行した検証コマンドとその結果、未検証のランタイムやプラットフォームの挙動を報告してください。公開の PR とコミットのテキストは貢献内容に集中させ、ローカル環境の詳細や私的な調査は省いてください。CONTRIBUTING.md に記述されたとおり、英語の Conventional Commit メッセージを使ってください。

`AGENTS.md` が正典のコントリビューターガイドであり、`CLAUDE.md` はそれへの相対シンボリックリンクです。このファイルを 1 回だけ編集してください。パッケージの所有権、検証コマンド、貢献ポリシーが変わった場合は、同じ変更の中で影響を受ける指示を更新してください。チェックインされたソースへリンクし、メンテナーのローカルメモ、ツール、絶対パスなしで新しいクローンから使えるガイドに保ってください。
