# デプロイ方式


デプロイ
Haizakura の各デプロイ方式の比較と選択

Haizakura はさまざまな環境で実行できますが、中核となる要件はどれも同じです。QQ を動かせること、QQ プロセスへ hook を注入できること、QR コードでログインできること。環境ごとに難易度は大きく異なります。次の表で適した道を選んでください。

どれを選べばよいか分からない場合は、クイックスタートの判断表を参照するか、迷わず **Docker on Linux** を選んでください。

## デプロイ方式の比較

| 方式 | プラットフォーム | 難易度 | 推奨 | 適した場面 |
|---|---|---|---|---|
| Docker | Linux | 低 | ✅ 最も推奨 | サーバーでの長期運用、すぐに使える |
| ワンクリックインストール | Linux | 低 | ⚠️ Alpha 実験 | 1 コマンドで Docker / sidecar / ローカルを導入、テスト中 |
| Windows 手動 | Windows | 中 | 任意 | Windows のローカルマシンで、Docker を入れたくない場合 |
| Windows · Docker Desktop | Windows | 中 | 任意 | Windows 上でコンテナ分離を使いたい場合 |
| WSL2 | Windows + WSL | 中 | 任意 | Windows 上で Linux サブシステムを使ってコンテナを実行 |
| Linux 手動 | Linux | 高 | ⚠️ 上級 / 非公式 | Docker イメージの内部を理解したい、または Docker を使えない場合 |
| スマートフォン | Android | 非常に高 | ⚠️ 上級 / 実験的 | Android スマートフォンしかなく、リソースが厳しく、注入が制限される可能性がある |
| 宝塔パネル | Linux | 低 | コミュニティ案 | 宝塔パネル導入済みで、Docker アプリストアからワンクリックで取り込む場合 |

Tip

**Linux 上の Docker が最も推奨され、最も手軽な方式です** —— イメージには QQ + Xvfb + VNC + noVNC + supervisord がすべて同梱されており、ホスト側に必要なのは Docker だけです。

Warning

**Linux 手動**と**スマートフォン**のデプロイは上級 / 非公式の経路です。手順が多く、落とし穴も多く、制限された環境（proot など）では注入が使えない可能性があります。何をしているか明確に分かっていない限り、Docker を優先してください。

## アップグレード

アップグレードの方法はデプロイ経路によって異なりますが、いずれも**ログイン状態と設定を失わないこと**を前提とします。詳細は 更新 を参照してください。
