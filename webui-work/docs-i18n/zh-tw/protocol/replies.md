# 回覆目標


一般的 OneBot `reply` 區段以非零的有號 `message_id` 識別訊息。負數識別碼是有效的。一般傳入訊息與傳送結果的識別碼產生規則維持不變。

私人 QQ 引用可以使用傳送者端序號，而不是用於訊息識別碼的會話序號。Haizakura 會把會話、傳送者方向、可用時間戳與引用文字，拿去和已儲存的訊息比對。來自不同序號命名空間的相同數字，本身並不能證明兩筆記錄指向同一則訊息。目前的訊息會從自身的引用查詢中排除。

當目標在本機無法取得時，即時事件處理會在轉換與分派事件之前，先請求有界的私人歷史。經驗證的歷史訊息會以其實際識別碼儲存，因此緊接著的 `get_msg` 可以取回它。填補缺少的內文時會保留既有的已驗證識別碼，而被回收的訊息不會被還原。

未解析或有歧義的私人目標不會產生猜測的識別碼，也不會產生新的佔位記錄。一般事件會省略該 `reply` 區段，並保留訊息其餘部分。警告會指出未解析的目標；追蹤日誌會記錄查詢結果、會話、序號、時間戳與選定的識別碼，但不記錄引用內容。取得失敗仍會保持可見。

群組引用保留其群組序號查詢。轉發節點保留其內嵌引用內容，即使原始訊息在本機帳號的歷史中無法取得，仍可重新送出。

圖片上傳會在持久訊息中介資料中保留其下載參照與實際檔名。`get_msg` 會依該訊息自己的參照重新整理每張圖片，因此重複使用的檔名或重新啟動都不會選到另一個上傳。

對於缺少圖片參照的較舊記錄，`get_msg` 會為已儲存的會話與序號（或舊式私人記錄的已儲存時間戳與用戶端序號）請求有界的歷史。只有唯一且傳送者、時間與有序圖片指紋都相符的訊息，才能填補缺少的參照。修復結果會儲存在既有的有號 `message_id` 之下；它會保留訊息內容與身分中介資料，且絕不還原在請求待處理期間被移除的記錄。完整的圖片不需要歷史請求。若歷史無法取得或無法驗證相符，未經驗證的圖片資料會原樣保留，並記錄一則警告；不會猜測下載 URL。
