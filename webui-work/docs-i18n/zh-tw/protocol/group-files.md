# 群檔案傳送與暫時儲存


`upload_group_file` 和 `send_group_msg` 中的檔案區段預設使用群永久檔案空間。
當伺服器明確傳回容量或檔案數量限制時，Haizakura 會嘗試一次暫時儲存，並在日誌中記錄這次切換。
暫時申請、檔案傳輸或聊天發佈失敗仍會回報錯誤；權限不足、連線失敗等其他錯誤不會觸發切換。
暫時檔案可能過期，不能作為永久儲存的替代。

## 訊息內容限制

進入暫時檔案路徑時，一則訊息只能包含檔案或圖片區段。
含文字、提及、表情等其他內容的混合訊息會被拒絕，需要呼叫端拆成獨立訊息後再傳送。
合併轉發會按每個節點的內容檢查同一規則。

Haizakura 會在發佈聊天訊息前檢查附件；發現不允許的組合時，不會先送文字、再丟掉附件或文字。
檢查之前已完成的其他附件上傳不會自動刪除。上傳成功後如果聊天發佈失敗，錯誤仍會保留檔案識別碼。
這不是跨多則訊息的交易：開始發佈後出現的網路或伺服器端錯誤，仍可能使前面的訊息已經送達。

一般圖片加文字仍透過圖片訊息通道傳送，不會因為群永久檔案空間不足而轉成群檔案。
永久檔案與文字的現有分開傳送方式保持相容。超大影片按原有規則轉成檔案後，也適用暫時檔案的內容限制。

## 檔案重複使用與下載

運作期間上傳過的群檔案會按帳號、群和檔案識別碼保留其儲存類型。
同一群中用 `file_id` 再次傳送、取得下載連結或產生合併轉發時，會使用該儲存類型。
`get_group_file_url` 明確傳入的 `busid` 仍優先；未提供有效值時，使用目前工作階段記住的類型，否則沿用永久檔案預設值。
上傳記錄不是持久化目錄；重新啟動後要取得暫時檔案連結，應從群檔案清單取得對應的 `busid` 並傳入。
