# Haizakura WebUI


Haizakura 的瀏覽器主控台是一個 Vite + React 應用程式，用來管理執行環境狀態、OneBot 設定、日誌、儲存與伺服器設定。

## 預設外觀

全新安裝與外觀重設使用吉祥物的薰衣草強調色。
淺色變體使用較深的紫色以確保按鈕標籤可讀；深色模式使用較柔和的薰衣草色。既有的已儲存強調色與自訂色彩會被保留。
原本的天藍色強調色仍可在設定中選用。

使用預設調色盤時，頁面、卡片、輸入框、彈出層與側邊欄表面會把少量作用中的強調色混入中性的淺色/深色背景。文字保持中性以維持可讀性。僅限側邊欄的強調色只會為側邊欄上色；OLED 保持真正的黑色畫布。具名調色盤、自訂 CSS 變數與主機外觀疊加層仍各自掌控其表面。

變更預設強調色時，請讓 `packages/core/src/webui/ui-config.ts` 中的伺服器預設值、`src/contexts/ThemeContext.tsx` 中的前端預設值與預設集，以及 `src/index.css` 中的掛載前權杖保持一致。

瀏覽器 favicon、主畫面圖示與應用程式內標誌共用
[`assets/brand/mascot-avatar.png`](../../assets/brand/mascot-avatar.png) 中的吉祥物頭像。
其匯出尺寸位於 `public/`：`logo.png`（512 px）、`favicon.png`（64 px）
與 `apple-touch-icon.png`（180 px）。請從母檔匯出，不要重繪個別尺寸。

## 主機外觀整合

`SNOWLUMA_WEBUI_TARGET=maibot` 會讓部署選擇啟用可還原的 millennium
外觀疊加層。獨立部署的預設值不變。主機可驅動即時的淺色/深色更新，而不會覆寫個人偏好或新增另一個選擇器。
變更目標啟動、主題歸屬、主機訊息或限定範圍樣式之前，請先閱讀[整合契約與擴充指南](INTEGRATIONS.md)。

## 互動慣例

- 破壞性動作與二次確認一律留在強制回應對話框中。
- 可能耗時的操作會在右下角顯示執行中狀態。
- 完成與失敗的操作使用右下角結果通知，並在可見的倒數結束後自動關閉。
- 例行、高頻的調整不應為每一次中介編輯都產生通知。
- 前景輪詢在分頁隱藏時暫停，並在排定下一次之前等待每個請求完成。連線狀態輪詢只在 SSE 用戶端訂閱期間執行。
- 以資料為基礎的表面使用 Interior Skeleton Swap 預設值（延遲 120 ms、
  最短可見時間 380 ms），讓快速的在地回應不會閃出佔位內容。
  提交、上傳與其他明確操作的進度仍保留其旋轉指示器。
- 高度可變的內容必須在就緒後釋放骨架預留的區塊；不要在頁面內引入第二個捲動區域。
- 行動版導覽選單使用受控的 Icon Morph，其視覺狀態跟隨實際的抽屜狀態。
- 失敗必須在受影響的控制項與操作結果中保持可見；不要把失敗的回應轉成成功的回饋。
- JSON 端點必須回傳物件。格式錯誤或非物件的回應會回報為錯誤，而不是顯示為空清單或預設設定。
- 設定回應包含 `config`；儲存時也會回報 `saved`、`applied`、
  `online`、`errors` 與 `message`。UI 使用這些欄位，不依賴舊式別名，也不在儲存後再發第二次請求。
- 變更密碼流程一致使用浮動標籤與行內驗證。
- 密碼強度細節只在新密碼欄位取得焦點時出現，並在焦點移開時以相同的動態語言離開。
- 首次執行精靈以同意條款文字為主要閱讀表面，並把每個步驟的動作對齊在同一個響應式頁尾。設定中包含一個可見的開發者頁面，可安全地重播此精靈並演練頁面層級的當機畫面；重播的同意與密碼永遠不會被持久化。

## 反向代理後的驗證

已驗證的 WebUI 請求會在 `X-SnowLuma-Token` 中送出會話權杖，讓
`Authorization` 保留給反向代理的 HTTP 驗證（例如 Nginx Basic Auth）。如果代理會過濾請求標頭，請原樣轉送 `X-SnowLuma-Token`。當專用標頭不存在時，後端仍接受既有用戶端的 `Authorization: Bearer <token>`。兩層都仍需各自有效的憑證。

來自舊會話的延遲驗證失敗不會把較新的會話登出。
即時串流在斷線時釋放訂閱，並隨頁面暫停。
格式錯誤的串流資料會被回報；除錯用的串流呼叫會失敗，而不是默默成功。

## 行程帳號偵測

行程卡片在注入前使用 QQ 的本機帳號資料，登入後使用 hook 確認的身分。缺少本機資料意味著帳號未知。這不能證明 QQ 已登出，而單憑本機偵測永遠不會把橋接標記為上線。
手動登入探測與 `/api/processes/:pid/probe-login` 端點已被移除。

Linux 從每個 QQ 行程的 `XDG_CONFIG_HOME` 或 `HOME` 解析資料根目錄。
Windows 使用隨附 addon 的 `getFileHoldersAsync` 找出持有各帳號資料庫的行程。查詢失敗會被回報，而不是當成未登入。

## 帳號通知範本

Webhook 主體與電子郵件主旨/主體支援 `{uin}`、`{nickname}`、`{event}`
（`offline` 或 `online`）、`{time}`、`{status}`（Hook 行程狀態）、`{pid}` 與
`{error}`（Hook 行程錯誤）。新的 webhook 與電子郵件管道會在其預設主體中包含行程狀態；既有的已儲存範本會被保留。
JSON 範本會轉義被代入的字串，包括引號、換行與控制字元。

行程事實會在通知被分派時解析，也就是在任何離線去抖動之後。每次轉換都帶有其行程 PID，包括帳號離線時被分離的最終 PID。事實會針對該 PID 與 UIN 查詢，不會代入另一個行程。缺少的事實會呈現為空並代表未知，而不是 QQ 已結束的證據。單憑 Hook 狀態無法指出 QQ 登入失敗的原因。同一個帳號的通知會依轉換順序遞送；慢速的帳號不會延遲其他帳號。

## 本機開發

套件化安裝在「設定 → 關於」中提供下載與重新啟動控制項。
下載會經過驗證與暫存；檔案會在應用程式啟動前套用。
重新啟動確認使用共用的強制回應對話框，下載結果使用動作回饋。

在 Windows 上，原生 API 會在啟動時記錄一次行程權杖與 EXE 完整性標籤。Low（或更低）權杖會觸發 WebUI 警告；單憑檔案標籤與查詢失敗不會。「臨時關閉」在此分頁工作階段期間有效，包括重新載入；「永久關閉」會保存在此瀏覽器的網站儲存中。兩者都不會抑制啟動日誌。失敗的查詢與偏好寫入會保持可見。

從儲存庫根目錄：

```bash
pnpm --filter webui dev
pnpm --filter webui typecheck
pnpm --filter webui lint
pnpm --filter webui test
pnpm --filter webui build
```
